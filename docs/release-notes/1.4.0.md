# 1.4.0 Release Notes

Released: 2026-10-17

## Summary

`1.4.0` fixes the thermostat mode control feature introduced in `1.3.0` so a requested `Off` actually reads back as `Off` in the Home app, and ports two robustness fixes from community forks.

## Highlights

- Fixed: turning a thermostat `Off` no longer bounces back to `Heat` in the Home app. Standby is now recognized by a manual or hold mode parked at the minimum setpoint (10 °C / 50 °F), which is exactly how the plugin requests it, so the `Off` state survives the read-back
- Fixed: an auto schedule combined with a manual operating mode is no longer misread as `Off`; scheduled runs always report `Auto`
- Fixed: non-JSON Nuheat API or OAuth token responses (e.g. an HTML login page) now log a warning and fail gracefully instead of throwing an unhandled parse error
- Fixed: a failed away-mode switch write acknowledges HomeKit and re-reads the group, so the switch reconciles with the real state instead of wedging the Home app

## Upgrade Notes

- No configuration changes are required; this is a drop-in upgrade for all `1.3.x` installations
- Users with **Thermostat Mode Control** enabled should see `Off` requests stick in the Home app immediately after updating
- Users who previously saw the tile flip back to `Heat` after tapping `Off` can confirm the fix by turning a thermostat off and watching the tile stay `Off` with a 10 °C setpoint
