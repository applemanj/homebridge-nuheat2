# 1.3.0 Release Notes

Released: 2026-10-15

## Summary

`1.3.0` adds an opt-in thermostat mode control feature backed by Nuheat's v2 mode API, and fixes two write-path defects found during a month of live testing.

## Highlights

- New `enableThermostatModeControl` setting (default `false`). When enabled, thermostats advertise `Off`, `Heat`, and `Auto` target states instead of heat only
- `Off` puts the thermostat in Nuheat standby (permanent manual hold at the minimum setpoint); `Auto` resumes the Nuheat schedule; `Heat` holds the current setpoint for the configured `holdLength`
- The HomeKit target state is now derived from Nuheat's `operatingMode`/`scheduleMode` fields, replacing a legacy switch that returned `Heat` in every branch
- Fixed: setpoint writes no longer push the empty `204 No Content` response into HomeKit, which briefly flashed `0.2 C` / `10 C` readings and a wrong target state after every change
- Fixed: heat-mode requests no longer send a stale cached setpoint, which could silently clobber a concurrent setpoint write from the Home app

## Upgrade Notes

- Existing configurations are unaffected; the new feature is off by default
- To try mode control, enable **Thermostat Mode Control** in the plugin settings (or set `enableThermostatModeControl: true`), then restart Homebridge and re-pair or refresh the accessory in the Home app
- The feature was verified over a month of live runtime on a real thermostat, including concurrent mode + setpoint changes from the Home app
